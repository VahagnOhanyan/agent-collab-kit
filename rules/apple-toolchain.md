# Xcode, симуляторы и телефон — общий ресурс машины (правило для всех проектов и агентов)

Уровень пользователя, как `orchestration.md`: источник — `~/agent-collab-kit/rules/apple-toolchain.md`,
установщик кладёт копию в `rules/` каждого конфига Claude Code. Действует для **всех** сессий
всех проектов машины, для их субагентов и для внешних агентов. **Правила проекта важнее**, но ни
одно не отменяет замок.

Почему: служба симуляторов одна на машину. Пока одна сессия запускала приложение на симуляторе и
собирала под телефон, тесты другой трижды падали — чужие `simctl`/сборки сбивали создание клона
тест-раннера (`(ipc/mig) server died`, `No matching device … in set …/XCTestDevices`,
`Channel disconnected`). Замок был только у тестового скрипта одного проекта.

## Основной и бета Xcode — роли

Какие версии и где стоят на конкретной машине — в личном слое её владельца (`rules/personal.md`).

| Xcode | Для чего |
|---|---|
| **основной** (выбран `xcode-select`) | всё, что собирается, тестируется и уходит в TestFlight; CI собирает релиз на той же версии |
| **бета** | только симуляторы новой iOS и устройства, которых нет в основном: `DEVELOPER_DIR=<путь к бете>/Contents/Developer <команда>` в одной команде |

- `sudo xcode-select -s …` **не выполнять**: он переключает Xcode всем сессиям машины сразу.
- Бетой не собирать релиз и не гонять тесты, по которым принимается работа (App Store не
  принимает сборки бета-Xcode; локальный компилятор должен совпадать с релизным CI).
- Переход на новую версию — отдельная задача владельца: CI, скрипты тестов, один полный прогон,
  потом удаление старой. Не по ходу другой работы.

## Замок машины — одна очередь на всё

Любая **работа с Apple-инструментами** идёт только через обёртку
`~/agent-collab-kit/bin/apple-lock <команда…>` (один замок `/tmp/apple-dev.lock` на машину):

- `xcodebuild` — сборка, `build-for-testing`, `test`, `test-without-building`, `archive`;
- `xcrun simctl boot | shutdown | erase | install | launch | clone | delete`;
- `xcrun devicectl device install | uninstall` и короткий `process launch` без `--console`;
- любой скрипт, который это вызывает (проектные тестовые скрипты берут замок сами — повторно
  оборачивать их не нужно: вложенный вызов под взятым замком идёт без ожидания).

Чтение без изменений (`simctl list`, `devicectl list`, `-showdestinations`, `xcodebuild -version`)
замка не требует. **Живой захват консоли телефона** (`devicectl device process launch --console`)
идёт без замка: он длится, пока владелец водит пальцем, и службу симуляторов не трогает; под
замком — сборка и установка перед ним.

**Порядок:**
1. **Ждать, а не отнимать.** Занято — обёртка сама ждёт (до 60 мин) и раз в минуту пишет, кто
   держит замок (`/tmp/apple-dev.lock.owner`: проект, процесс, команда, время). Чужие процессы
   `xcodebuild`/`simctl`/`devicectl` не убивать, чужие симуляторы не выключать и не стирать,
   клоны в `~/Library/Developer/XCTestDevices` не трогать.
2. **Одна операция — один захват.** Замок держат на время команды, а не сессии: не брать его
   «впрок», не держать, пока ждёшь ответа владельца или ревьюера. Долгий захват (полная сборка,
   прогон пачки классов) — сообщить в отчёте, сколько длился.
3. **Прогон упал с `server died` / `Channel disconnected` / `No matching device`** — это не
   дефект кода. Посмотреть, кто держит замок или гонял симулятор мимо него
   (`~/Library/Logs/CoreSimulator/CoreSimulator.log`), и повторить после — не «чинить» тест.
4. **Долгое ожидание** (больше 20 мин) — сказать владельцу, кто держит, а не молча висеть.
5. **Телефон** — прежнее правило: установка только после слова владельца, и тоже под замком.

## Кто проверяет

Замок держится механизмом, а не уговором: проектные скрипты тестов и запуска берут его сами.
Прямой вызов из списка выше мимо `apple-lock` — нарушение, которое `verifier` называет в отчёте
(транскрипт ведущей: команды `xcodebuild`/`simctl`/`devicectl` без обёртки).
