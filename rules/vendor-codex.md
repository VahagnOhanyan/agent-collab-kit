# Адаптер вендора: Codex CLI

Ставится только на машины, где есть Codex (`codex` в PATH или `~/.codex`). Как вызывать; какие
роли Codex держит у конкретного человека, какие модели по умолчанию и какие у него лимиты — в его
личных правилах (`rules/personal.md`), не здесь.

## Вызов

`codex exec -m <slug> -c model_reasoning_effort=<уровень> -s read-only -C <каталог> -o <файл> "<промпт>" [-i <картинка>…] </dev/null`, в фоне.

- `-m` — всегда явно, slug из `collab models` под нужный уровень: дефолт `~/.codex/config.toml`
  обычно самый дорогой. `--output-schema <json>` — когда нужен разбираемый ответ.
- Промпт — до `-i` (флаг вариадический). MCP-инструменты у Codex отложены — в промпте «найди их
  через tool search».
- `</dev/null` всегда: в фоне `codex exec` иначе ждёт stdin и висит.
- По умолчанию `-s read-only`. Codex пишет код только в выделенной копии (worktree) с разрешения
  владельца и по правилам записи проекта.
- Вывод — в приватный каталог (`mktemp -d`, `chmod 700`), не в предсказуемое имя в общем `/tmp`.
- Живой каталог моделей вендора — `~/.codex/models_cache.json`; остаток лимита — события
  `token_count` в `~/.codex/sessions/`.

Скиллы этого адаптера: `codex-review` (ждущие ревью в collab, включая роль `ux_reviewer`),
`ui-review` (варианты дизайна).
