# Хуки комплекта: модель угроз и границы гарантий

Коротко: `scope-guard` и `readonly-guard` — **предохранитель от ошибок и
промпт-инъекций агента, а не песочница**. Они надёжно отменяют *вызовы
инструментов*, которые явно выходят за область, но не изолируют процесс.

## Как хуки запускаются

Хуки — модули Node (`hooks/<имя>.mjs`), один код для macOS и Windows. Хост
вызывает лаунчер: `node "$HOME/.agent-collab-kit/current/bin/agent-collab-kit-hook" <имя>`
во frontmatter агентов (`|| exit 2` на конце), абсолютные пути к node и
лаунчеру — в `~/.codex/hooks.json`. Лаунчер сам превращает в блок (код 2) всё,
что иначе стало бы пропуском: неизвестное имя хука, сбой загрузки модуля,
падение `main`, нецелый код. Хук-граница экспортирует `failClosed = true`:
если stdin не закрылся за 4 с, лаунчер блокирует сам, не дожидаясь, пока хост
убьёт его по таймауту. Остальные хуки (`model-guard`, `codex-guard`,
`plan-gate`, `push-gate`, `post-edit`, `session-start`, `context-watch`) при таком сбое
пропускают: это не граница безопасности, а страховка ведущей сессии
(`push-gate` блокирует красный гейт и обходы `git push`, но не защищает от
человека, который пушит из своего терминала).

`push-gate` работает по модели «блок при сомнении» (с 29.09.2026, после
четырёх раундов ревью, находивших расхождения самописного разбора с bash).
Оболочку он не разбирает. Если в команде (после склейки `\`+перевод строки,
снятия пустых склеек `$''`/`$""`/`${…}`/`$@`, кавычек и `\`) есть слово `git`
и `push` — или `git` вместе с `$'…'` или `autocorrect`, которые прячут слово
push, — он пропускает только доказуемо простую команду:
- без `$`, обратных кавычек, `<<`/`<<<`; без скобок, блоков `{ }`, фона `&`
  и ключевых слов оболочки; операторы — только `&&`, `||`, `;`, перевод строки,
  `|`;
- push — это `git [-C <каталог>] [--no-pager] push <аргументы>`: без `-c`,
  `--git-dir`, `--work-tree` и других глобальных опций, без присваиваний
  `NAME=…`;
- другие подкоманды git рядом со словом push — только из списка тех, что не
  исполняют аргументы (`commit`, `log`, `stash`, `checkout`, `branch`…);
  `rebase -x`, `submodule foreach`, `bisect run`, `config alias.*`,
  `grep -O`, `fetch`/`pull --upload-pack` — блок (grep, fetch, pull в список
  не входят);
- другие программы, упоминающие push, — только `echo`/`printf`/`grep`/`rg`;
  оболочки, `eval`, `xargs`, `env`, `sudo`, `arch`, `xcrun`, `export`, `alias`,
  `set`, `pushd`/`popd` и подобные в такой команде — блок;
- вывод команды, упоминающей push, по конвейеру (`|`, `|&`) — только в
  читатели (`head`, `tail`, `cat`, `tee`, `grep`, `wc`…), а не в интерпретатор
  (`| tcsh`, `| python3`);
- `cd` — в существующий каталог, не `cd -`, не в конвейере, не рядом с `||`, и
  безусловный: в начале цепочки `&&` или перед push в той же цепочке.
Всё остальное — блок с просьбой запустить push отдельной простой командой.
Каталог push известен всегда: иначе блок, а не каталог сессии. `git -C` и
`cd -P` разрешаются физически (как chdir: `..` после симлинка), `cd` —
логически, как в bash. Ненулевой код выхода collab — сбой, как и таймаут. Обходами
считаются `--force*` (и сокращения), `-f` в кластере (`-uf`), `+ref`, `:ref`,
`--mirror`, `--delete`/`-d`, `--prune`, `--no-verify` (и сокращения).

Проект, у которого объявлен `gate`, fail-closed: битый `project.json` (схема
проверяется функцией самого collab `readProjectEntry`), гейт без файла, ошибка
запуска или исчерпанный бюджет — блок. collab ответил с `error` или не ответил
вовсе — блок, если какая-либо запись реестра заявляет этот каталог в `roots`
(ищется в реестре из ответа и в обоих местах по умолчанию:
`~/.agent-collab-kit/projects`, `~/.agent-collab-kit/current/projects`). Проход — только
там, где защищаться нечем: набор collab не установлен, каталог не заявлен ни
одной записью, в реестре нет ключа `gate`.

Граница (принято): хук ловит ошибки и случайные обходы ведущей сессии, а не
целенаправленный обход. Он не видит:
- команду, где слова `git` или `push` собраны из переменных или глоба
  (`g=gi; ${g}t …` — `$` уже блокирует, но `/usr/bin/gi?` — нет);
- алиасы git из `~/.gitconfig` и `.git/config` (`git p` при `alias.p = push -f`),
  `core.hooksPath` и `GIT_CONFIG_*`, заданные раньше в окружении сессии или в
  конфигурации, а не в самой команде;
- скрипт или программу, которые пушат сами (`./release.sh`, `make deploy`),
  и `git send-pack`;
- запись реестра, нечитаемую по правам: к каталогу её не привязать, и она не
  блокирует чужие проекты.
Ложные блоки — цена модели: команду с push, где есть `$` (даже в кавычках),
heredoc или скобки вне кавычек, — например `git commit -m "$(cat <<EOF …)" &&
git push`, — придётся разбить на две команды.

## От чего защищаем

- Субагент `implementer` по ошибке или из-за инъекции в прочитанном тексте
  правит файл вне своей области через Edit/Write/NotebookEdit: чужой модуль,
  `CLAUDE.md`, `.git/`, `.claude/`, `.mcp.json`, настройки `~/.claude`,
  `~/.codex` или сам комплект (`~/agent-collab-kit`, `~/.agent-collab-kit`).
- Субагент `verifier` «чинит» то, что должен только измерить: меняет дерево,
  git, зависимости, файлы — через Bash.
- Подмена областей через окружение: области берутся только из реестра
  владельца (`<registryDir>/<projectId>/scopes.json`), путь к `collab`
  фиксирован (`$HOME/.agent-collab-kit/current/bin/collab`), переопределений нет.

## Что `scope-guard` гарантирует (для одного вызова инструмента)

- Любой нештатный исход — exit 2 (блок): мусор/пустое/не-UTF-8 событие, NUL
  в пути, неизвестный `tool_name`, нет или относительный `cwd`, одновременно
  `file_path` и `notebook_path`, сбой/таймаут `collab` (5 с), битый
  `scopes.json`, любое исключение, незакрытый stdin (4 с), сторож 10 с
  (вместе 14 с при таймауте хука 15 с). Строка запуска `node … || exit 2`
  превращает в блок и отсутствие node или лаунчера, и любой другой ненулевой код.
- Жёсткие запреты проверяются первыми, по лексическому пути и по realpath;
  исключение для `/tmp` действует только вне git-репозиториев.
- Сравнение путей и шаблонов — после NFC + свёртки регистра, по границе компонента:
  регистровые и юникодные псевдонимы на APFS не обходят `deny`.
- Запись в существующий файл с несколькими жёсткими ссылками блокируется.
- Копия задачи (`collab worktree add`) лежит под служебным `.claude/worktrees/`
  корня. Внутри копии, записанной в `<корень>/.collab/worktrees.json` как
  `kind: task`, лежащей строго внутри корня и имеющей файл `.git`, корнем
  считается сама копия: служебные имена, `allow` и `deny` проверяются
  относительно неё. Снимок (`kind: snapshot`), запись другого вида, копия без
  файла `.git` и битый `worktrees.json` — блок; незаписанная копия под
  `.claude/` — по-прежнему служебный путь. Заявку задачи внутри копии держит
  `claim-guard`.

## Что `claim-guard` гарантирует (для одного вызова Edit/Write/NotebookEdit)

Он держит не область агента, а **заявку задачи** — и только внутри рабочей
копии, которую журнал привязал к задаче (`collab worktree add` →
`.collab/worktrees.json` в корне журнала, поле `worktree` на задаче).

- Дерево, которого нет в `worktrees.json` (основное дерево проекта, копия
  Codex, чужой репозиторий, каталог вне git), — **пропуск**: ведущая сессия и
  интеграция работают как раньше. Нет `worktrees.json` — пропуск.
- Внутри привязанной копии — fail-closed: путь цели (относительно верхнего
  уровня копии) обязан пересекаться с `files` задачи по той же префиксной
  логике, что `claim_files`; задача обязана быть `in_progress`/`assigned`, с
  владельцем и живой lease. Иначе — exit 2 с подсказкой, какой вызов
  (`claim_files <id> [путь]` или `claim_task <id>`) снимает блок. Снимок
  (`kind: snapshot`) — только чтение.
- Любой нештатный исход в привязанной копии — блок: битый или нечитаемый
  `worktrees.json`/запись задачи, таймаут git (3 с), сторож 10 с, незакрытый
  stdin (4 с, `failClosed`). Битый `worktrees.json` блокирует и основное
  дерево — выяснить, привязано ли оно, без него нельзя; сообщение называет файл.
- Он не запускает `collab`: два чтения JSON и один `git rev-parse`
  (фиксированные пути к git, чистое окружение). Поэтому стоит миллисекунды и
  не зависит от того, установлен ли набор в `$HOME` — только от файлов журнала.
- Что он не делает: не проверяет область агента (`scope-guard`), не мешает
  агенту НЕ создавать копию и править основное дерево — это правило проекта
  («один пишущий агент на дерево»), а копию создаёт ведущая сессия. Не
  различает агентов внутри одной копии: заявка — у задачи, не у процесса.

## Что `readonly-guard` делает (для одной команды Bash)

**Это allowlist с запретом по умолчанию.** Хук не ищет опасное — он
проверяет, что вся команда состоит только из разрешённого. Всё, чего он не
понимает, блокируется. Два независимых ревью показали, что предыдущий denylist
по регулярным выражениям не удерживался (подстановка в `/tmp/$p`,
`git -c alias.x=commit x`, `git -c core.pager=… -p log`, функции shell,
`vim -es -c`, `arch … osascript`, `xcrun simctl --set … erase`); все эти случаи
теперь — тесты на блок.

- **Fail-closed.** Любой нештатный вход — exit 2 с русским сообщением: пустое,
  не-JSON, не-UTF-8 событие, NUL, событие не объект, `tool_name` не `Bash`, нет
  строки `command`, любое исключение внутри хука. Незакрытый stdin — 4 с,
  сторож проверки — 5 с (вместе 9 с при таймауте хука 10 с). Строка запуска —
  `node … || exit 2`: нет node, лаунчера или файла хука — блок.
- **Токенизатор консервативный.** Кавычки разбираются; всё, что shell мог бы
  истолковать иначе, чем видит хук, — блок: `$` в любой форме (`$VAR`, `$(…)`,
  `${…}`, `$'…'`, `$IFS`), обратные кавычки, `(`, `)`, `{`, `}`, `<` в любой
  форме (heredoc, here-string, `<(…)`, `< файл`, `</dev/fd/…`), `&` (фон, `&>`,
  `|&`), `\` вне кавычек (в том числе перенос строки), `~`, `!`, `#`,
  слово с `=` в начале, управляющие символы, незакрытые кавычки, пустые
  сегменты (`;;`, `| |`, ведущий/замыкающий оператор). Из перенаправлений
  разрешены только `>/dev/null`, `2>/dev/null`, `2>&1`; `> /tmp/…`, `>>`,
  `>&2`, `2>файл` — блок.
- **Простые команды.** Команда делится по `;`, переводу строки, `&&`, `||`, `|`;
  каждый сегмент обязан быть разрешённой простой командой (конвейер — только
  между разрешёнными). Присваивание перед командой (`VAR=x cmd`, `p=../..`),
  слово команды в кавычках (`"r"m`) или с глобом, функции, `alias`, `eval`,
  `exec`, `source`, `.`, `env cmd`, `command` (кроме `command -v`), `sudo`,
  `nohup`, `nice`, `timeout`, `time`, `arch`, `xargs`, `cd` — блок.
- **Allowlist по слову команды** (точное имя или `/bin/…`, `/usr/bin/…` с тем
  же именем), у каждого — своя политика аргументов; опасные флаги проверяются
  по *значению* аргумента, кавычки не помогают (`find . '-delete'` — блок):
  - **Читатели:** `ls`, `cat`, `head`, `tail`, `wc`, `stat`, `du`, `df`, `pwd`,
    `which`, `echo`, `printf`, `uname`, `whoami`, `id`, `grep`/`egrep`/`fgrep`,
    `cut`, `tr`, `jq`, `diff`, `cmp`, `comm`, `basename`, `dirname`, `realpath`,
    `readlink`, `shasum`, `md5`, `sw_vers` — любые аргументы; `env` — без
    аргументов; `command -v имя`; `date` — только `-…`/`+формат` (установка
    времени — блок); `file` — без `-C`/`--compile` и с известными длинными
    опциями; `rg` — без `--pre`/`--pre-glob`; `find` — без `-delete`, `-exec`,
    `-execdir`, `-ok`, `-okdir`, `-fprint*`, `-fls`; `sort` — без `-o`, `-T`,
    длинные опции только из известного списка (GNU-сокращения вроде `--out`
    — блок); `uniq` — не более одного позиционного аргумента; `plutil -p`/
    `-lint`; `xcode-select -p`/`--print-path`/`--version`. `jq` разрешён
    целиком: он не пишет файлы и не запускает программы (`--rawfile`/`-f`
    только читают).
  - **git — строгий список подкоманд, глобальные опции запрещены** (`-c`, `-C`,
    `--git-dir`, `--work-tree`, `--exec-path`, `-p`/`--paginate`, `-P`; единственное
    исключение — `--no-pager` первым словом, он влияет лишь на вывод).
    Разрешены: `status`, `diff`, `log`, `show`, `blame`, `ls-files`, `ls-tree`,
    `cat-file`, `rev-parse`, `rev-list`, `describe`, `shortlog`, `grep`,
    `merge-base` (у них — блок `--output[=…]`, `--output-*`, `--ext-diff`,
    `--textconv`, `--filters`; у `grep` ещё `-O`/`--open-files-in-pager`);
    `branch` только без аргументов или с `--list`, `-a`/`--all`, `-r`/`--remotes`,
    `-v`/`-vv`, `--show-current` (`--merged`, `--contains` и любое имя — блок);
    `worktree list [опции]`; `remote` без аргументов или `-v`; `config` ровно с
    одним действием `--get`, `--get-all`, `--get-regexp`, `--list`/`-l` (`get`/
    `list` новой формы тоже) и флагами области (`--global`, `--local`, …;
    `--file`/`-f`/`--blob` — блок); `stash list`/`stash show`; `tag` без
    аргументов или с `-l`/`--list` [+ `-n`]; `--version`. Неизвестная
    подкоманда — то есть любой алиас — блок.
  - **Раннеры, сборка, гейт** (исполняют код проекта — см. риски):
    `node --test …` (только `--test-*`-опции из списка, репортёры только
    встроенные, пути относительные без `..`) и `node --check <файл>`;
    `python3`/`python`/`/usr/bin/python3` только `-m unittest …` и `-m pytest …`
    (опции из списка; `-c`, `-o`, `--basetemp`, `--junitxml`, `--log-file`,
    `--cov*`, `-p` кроме `no:…` — блок; пути относительные без `..`);
    `npm test`, `npm run [<script>]`, `pnpm test`, `yarn test` — флаги менеджера
    до `--` блокируются (`--prefix`, `-w`), после `--` уходят скрипту;
    `swift build`/`swift test` с опциями из списка (`--package-path`,
    `--scratch-path`, `-Xswiftc`, `--xunit-output` — блок); `xcodebuild` только с
    действиями `build`/`build-for-testing`, опциями из списка (`-project`,
    `-workspace`, `-scheme`, `-destination`, `-sdk`, `-list`,
    `-showBuildSettings`, …) и настройками `CODE_SIGNING_ALLOWED`,
    `CODE_SIGNING_REQUIRED`, `CODE_SIGN_IDENTITY`, `ONLY_ACTIVE_ARCH`; `test`,
    `clean`, `archive`, `-resolvePackageDependencies`, `-derivedDataPath`,
    `-resultBundlePath`, `-allowProvisioningUpdates`, `-xcconfig`, прочие
    `KEY=VALUE` — блок; `bash`/`sh <относительный путь>` — без единой опции
    (`-c`, `-s`, `-x` — блок), файл после realpath обязан быть обычным файлом
    внутри `cwd` из события хука; любой компонент `..` в пути — блок, даже
    если путь возвращается внутрь (`scripts/../scripts/x.sh`): лексическое
    сворачивание `link/..` расходится с realpath; слово команды с `/` (`./x`,
    `scripts/x`, гейт) — тот же realpath-контроль плюс бит исполнения (на
    Windows бита нет — только «обычный файл внутри cwd»); абсолютные пути вне
    `/bin`, `/usr/bin` — блок. Нет абсолютного `cwd` в событии — блок для этих
    форм (читатели и git от cwd не зависят).
  - **Симулятор и реестр:** `xcrun simctl list …` (`-j`/`--json`/`-v`),
    `xcrun --find <tool>`, `xcrun --show-sdk-path` (и `--sdk X --show-sdk-path`);
    любой другой `xcrun`/`simctl` (`erase`, `boot`, `install`, `--set …`,
    `--run`, `xcrun swift …`) — блок. Эти команды и `swift`, `xcodebuild`,
    `xcode-select`, `plutil` — платформенная группа `apple`: проходят, только
    если проект включил её в реестре (`<registryDir>/<projectId>/readonly-guard.json`,
    `"platforms"`); проект не узнать — блок. `collab` — только
    `collab project [--json]` и `collab reviews [--task|--reviewer|--pending|--json]`.
- **Всё остальное — блок** с сообщением, называющим слово команды и
  предписывающим отметить шаг как «не проверено» или попросить лида. Это
  включает `curl`, `wget`, `sed`, `awk`, `perl`, `ruby`, `tee`, `xargs`, `make`,
  `npx`, `pip`, `brew`, `sqlite3`, `psql`, `docker`, `ssh`, `kill`, `open`,
  `vim`, `osascript`, `defaults`, `codesign`, `ps`, `sleep`, `true`, `test`,
  `[`, `cd` и любой бинарь по неизвестному абсолютному пути (`/opt/homebrew/bin/rg`).
- **Что verifier теперь не может из ранее разрешённого:** `node script.js`,
  `python3 script.py`, `perl`/`ruby` по пути, `curl` (даже GET), `sed -n`,
  `awk`, `git branch --merged/--contains`, `git submodule status`, `npm ls`,
  `npx tsc --noEmit`, `pip list`, `> /tmp/…`, `git -C dir …`, `make`, `cat *.md`
  без `./`. Всё это — «не проверено» + просьба к лиду.
- **Копия задачи — единственное исключение для `cd`.** Первая команда может
  быть `cd <каталог> && …`, если каталог по realpath совпадает с копией,
  записанной в `<корень>/.collab/worktrees.json` (корень — `codeRoot` из
  `collab project --json`), лежит строго внутри корня и имеет файл `.git`.
  Остальные команды проверяются тем же allowlist, но относительно копии.
  Любая другая форма `cd` (через `;`, с флагом, не первой, в корень, в
  незаписанную копию, с `..`) — блок.

## Остаточные риски (честно)

- **TOCTOU.** Хук проверяет путь, а запись делает хост позже. Если между
  проверкой и записью компонент пути подменят на симлинк (например, фоновой
  командой через Bash), запись уйдёт по новому адресу. PreToolUse-хук это
  закрыть не может; нужна запись через дескрипторы без следования симлинкам
  или песочница ОС. Не исправлено и не имитируется.
- **Bash не охраняется `scope-guard`.** У `implementer` есть Bash — это
  доверие, а не граница: `echo > file`, `sed -i`, `git`, скрипты пишут куда
  угодно.
- **`readonly-guard` — сопоставление с шаблонами, а не песочница.** Allowlist
  закрывает *синтаксис* команды, но не то, что делает разрешённая программа:
  - **Раннеры и гейт исполняют код проекта.** `scripts/preflight.sh`, `npm test`,
    `swift build`, `xcodebuild build`, `node --test`, `pytest` запускают
    произвольный код из дерева проекта (build phases, `package.json`-скрипты,
    тесты, плагины пакетов, `conftest.py`, `.mocharc`). Любой исполняемый
    обычный файл внутри cwd тоже проходит — включая скопированный в дерево
    интерпретатор (`venv --copies`, `.build/…`). Это **доверие к проекту**;
    единственная полная защита — песочница ОС (`sandbox-exec`, контейнер,
    отдельный пользователь с read-only монтированием).
  - **Конфигурация git из репозитория.** `-c` на командной строке закрыт, но
    `.git/config` и `.gitattributes` проекта могут задать `core.pager`,
    `diff.external`, `diff.*.textconv`, `filter.*` — `git log`/`diff`/`show`
    выполнят их. Кто может писать в `.git/config`, уже владеет репозиторием.
    `git status` обновляет stat-кеш в `.git/index` — это принятое изменение
    метаданных.
  - **Артефакты внутри проекта.** Сборка и тесты пишут в `.build/`,
    `DerivedData`, `node_modules/.cache`, `.pytest_cache`, `Package.resolved`
    (`swift build` может разрешить зависимости и выйти в сеть). Это не запрет
    хука, а свойство раннеров.
  - **Неполный разбор значений опций.** Хук ищет опасные флаги по всем
    аргументам, не различая опцию и её значение: `rg -e --pre f` блокируется
    (ложный блок, безопасно). Обратное — флаг, спрятанный так, что хук не
    видит, — возможно только через семантику самой программы (например,
    GNU-сокращения длинных опций; для `sort`/`file` поэтому длинные опции
    ограничены списком, для остальных читателей пишущих опций не найдено).
  - **Глоб в аргументах.** Незакавыченный глоб раскрывает shell, не хук.
    Разрешён только аргумент, начинающийся с литерала не `-` (`tests/*.py`),
    чтобы результат раскрытия не мог стать флагом; `*.md` — блок.
  - **Сеть и внешние сервисы.** `swift build`/`xcodebuild` могут скачивать
    зависимости; `collab project` читает реестр. `curl` закрыт целиком.
  - **cwd из события.** Проверка скриптов по пути опирается на `cwd`, который
    хост передаёт в событии; `cd` заблокирован, поэтому shell verifier не
    уходит из него. Если хост передаст не тот cwd, проверка «файл внутри cwd»
    ослабнет до «файл внутри того, что передали».
  - **Жёсткие ссылки.** realpath не видит hard link: `scripts/x.sh`, жёстко
    связанный с файлом вне проекта, пройдёт. Запуск читает, а не пишет, так
    что риск — исполнить чужой файл, лежащий в дереве под другим именем.
- **Процесс того же пользователя может править файлы и так.** Хуки не защищают
  от уже запущенного вредоносного кода, от других сессий и инструментов, от
  MCP-серверов с доступом к ФС.
- **Хост.** Таймаут хука, убийство процесса хостом или изменение семантики
  кодов выхода в Claude Code = пропуск. Внутренние сторожа заведомо меньше
  таймаутов во frontmatter, но гарантия держится на поведении хоста. Хук, не
  подключённый к агенту (другой `agents/*.md`, одноимённый проектный агент —
  например, проектный `verifier`, — MultiEdit и новые инструменты записи вне
  matcher), не работает вовсе.
- **Доверенные входы.** `$HOME`, `KIT_AGENT`, бинарь `collab`, реестр и
  `/usr/bin/git` считаются доверенными: кто может их менять, тот задаёт области.
- **Windows — код есть, живой проверки нет.** Ветки для Windows (пути с `\`,
  диски, `taskkill` дерева процессов, `USERPROFILE`) покрыты только чтением
  кода: тесты симлинков и POSIX-прав там пропускаются, и ни один прогон на
  реальной Windows ещё не сделан. Отдельно не проверено: какой оболочкой хост
  исполняет строку из frontmatter (нужен `sh`: `$HOME` и `|| exit 2`), и
  короткие имена 8.3 (`PROGRA~1`), которые realpath может не развернуть.
- **Сторож не прерывает синхронные вызовы ФС.** Зависший `stat` на сетевом
  томе держит поток: сторож сработает лишь после возврата, и хост успеет убить
  хук по таймауту (= пропуск).
- **`node` из PATH во frontmatter.** Агенты вызывают `node` по имени: кто
  подменит PATH хоста, подменит и хук. Отсутствие node — блок, не пропуск.
- **Регистр.** Свёртка рассчитана на регистронезависимый APFS. На
  регистрозависимом томе разные по регистру каталоги сольются: `deny` станет
  шире (безопасно), `allow` — тоже шире (может разрешить соседний каталог,
  отличающийся только регистром).

## Закрыто после третьего независимого ревью (13.09.2026)

- `printf -v NAME …` присваивал переменную оболочки (`printf -v PATH /tmp; cat`) — `printf` с `-v…` блокируется.
- `rg -z` / `--search-zip` запускали внешние распаковщики — блокируются, включая склейку коротких флагов.
- Пути с кодом для раннеров (`node --test`, `node --check`, `python3 -m unittest/pytest`, в том числе `-s`/`-t`/`--ignore`) и `xcodebuild -project/-workspace` проверяются по realpath внутри cwd: симлинк наружу и чужой проект — блок. Гонка «проверка → запуск» (подмена симлинка между ними) по-прежнему остаётся остаточным риском, см. выше.
