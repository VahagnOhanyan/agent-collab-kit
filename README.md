# agent-kit

Инструменты для совместной работы AI-агентов (Claude Code и Codex) в любом проекте на этой машине. Исходник — этот репозиторий; машина пользуется **установленным релизом** `~/.agent-kit/current`, а не рабочим деревом.

## Что внутри

| Часть | Что делает | Где |
|---|---|---|
| `collab` | Журнал агентов: задачи, ревью, решения, одобрения владельца. MCP-сервер + CLI | `collab/`, `bin/collab`, модель угроз — `collab/SECURITY.md` |
| `/codex-review` | Ручной запуск Codex на ждущие ревью из журнала | `skills/codex-review/` |
| `/ui-review` | Скриншот экрана → варианты дизайна от Codex → **одобрение владельца** → реализация → сравнение | `skills/ui-review/`, скрипты `ui-review/` |
| `implementer` | Агент-исполнитель; писать может только в области, заданные владельцем | `agents/implementer.md`, хук `hooks/scope-guard.py` |
| `verifier` | Агент-проверяющий, ничего не меняет | `agents/verifier.md`, хук `hooks/readonly-guard.py` |
| `model` обязателен в `Agent()` | Вызов субагента без явной `model` (кроме `subagent_type: "fork"`) отменяется до делегирования, а не ловится потом по транскрипту | `hooks/model-guard.py` — подключается в `.claude/settings.json` ведущей сессии проекта (`PreToolUse`, matcher `Agent`), не во фронтматтере субагента и без проектных данных |
| Правило оркестрации | План до первой правки, уровни L0–L3, маршрутизация, слоты проверок; ставится в `~/.claude/rules/` | `rules/orchestration.md` |
| Правило терминологии | Любая задача начинается со словаря «термин → имя в коде → что видно», который владелец подтверждает до работы; ставится в `~/.claude/rules/` | `rules/terminology.md` |
| Реестр проектов | Доверенные настройки каждого проекта (вне самих репозиториев) | `projects/<id>/` |

Работа между моделями распределяется в двух местах, и это разделение намеренное. **Данные** — здесь: `collab/config/models.json` — лестница уровней L0–L3 и то, какую модель каждый уровень означает у каждого вендора (`collab models` показывает её, `collab doctor` сверяет id с каталогом вендора и сообщает дрейф). **Суждение** — план до первой правки, какой уровень у задачи, когда эскалировать и сколько нужно независимых проверок — в `rules/orchestration.md` этого репозитория (с 17.09.2026; раньше жило только в `~/.claude/rules/` без истории). Установщик кладёт копию в `~/.claude/rules/orchestration.md`, откуда её грузит каждая сессия Claude Code; править — здесь, а не копию: изменённая руками копия остановит следующую установку. Имена моделей в коде и скриптах не живут; они живут в реестре. Границы и остаточные риски хуков — `hooks/SECURITY-hooks.md`.

## Установка, проверка, откат

Установщик берёт **только закоммиченное** состояние: грязное дерево он откажется ставить.

```bash
bin/agent-kit-install --dry-run      # все проверки и тесты, ничего не меняет
bin/agent-kit-install                # установка
bin/agent-kit-install --rollback     # вернуть предыдущий релиз
```

Что делает установка:
1. Проверяет, что в коммите есть все обязательные файлы.
2. Собирает релиз через `git archive` и прогоняет в нём тесты `collab`: должно быть 0 падений и 0 пропусков.
3. Делает дымовой тест MCP: сверяет полный список инструментов и что без журнала ничего не создаётся.
4. Атомарно переключает `~/.agent-kit/current`.
5. Раскладывает по домашнему каталогу то, что читают Claude Code и человек: `<каталог настроек>/skills/{codex-review,ui-review}`, `<каталог настроек>/agents/{implementer,verifier}.md` и `<каталог настроек>/rules/{orchestration,modules,terminology}.md` — **в каждом каталоге настроек Claude Code**, не только в `~/.claude`. На macOS/Linux все три — **настоящие копии** из установленного релиза (симлинк здесь Claude Code не видит, проверено 16.09.2026), владение отслеживается по хэшу в `~/.agent-kit/posix-copies.json`. На Windows каталоги скиллов — junction на `current` (единственная ссылка, доступная без прав администратора), а файлы агентов и правила — копии, по хэшу в `~/.agent-kit/windows-links.json`. Лаунчер `collab` — симлинк в bindir (по умолчанию первый существующий из `/opt/homebrew/bin`, `/usr/local/bin` на macOS/Linux, `%LOCALAPPDATA%\Microsoft\WindowsApps` на Windows), на Windows — `.cmd`-шим, потому что симлинк на файл там без администратора недоступен. Чужой файл на месте копии не перезаписывается: установка откажет и назовёт его.
6. Регистрирует MCP `collab` для Claude (уровень пользователя, отдельно в каждом каталоге настроек) и Codex (`~/.codex/config.toml`, с бэкапом). Каталог, чей `claude` не отвечает (например, у аккаунта отключён доступ), попадает в вывод строкой «NOT registered» — установка при этом доходит до конца: копии важнее регистрации, а зарегистрировать можно потом. Это касается **дополнительных** каталогов; в основном (`~/.claude`) сбой регистрации по-прежнему отменяет установку целиком.

**Несколько аккаунтов Claude Code.** У каждого аккаунта свой каталог настроек (`~/.claude`, `~/.claude-account-2`, …), и сессия читает скиллы, агентов и правила **только из своего** — проверено 18.09.2026 файлом-меткой в каждом каталоге. Поэтому копии нужны в каждом: по умолчанию установщик берёт `~/.claude`, добавляет каталоги из повторяемого флага `--claude-config-dir <путь>` и подхватывает `CLAUDE_CONFIG_DIR`, если тот указывает внутрь домашнего каталога (сравниваются реальные пути: симлинк наружу дома не пройдёт) (снаружи — игнорирует, чтобы прогон тестов со своим `--home` не задел настоящий аккаунт; явно заданный снаружи путь — ошибка). Подсказка про откат в конце установки уже содержит нужные `--claude-config-dir`.

Любой сбой откатывает всё, что успело измениться. После установки перезапустите открытые сессии Claude и Codex.

## Подключить проект

1. **Запись в реестре** — `projects/<id>/project.json`:
   ```json
   { "id": "myapp", "roots": ["/Users/<you>/myapp"], "gate": "scripts/check.sh" }
   ```
   - `roots` — корень репозитория. Все его worktree пишут в один журнал.
   - `gate` — необязательная команда проверки, её запускает `verifier`.
2. **Области записи для `implementer`** — `projects/<id>/scopes.json`:
   ```json
   { "implementer": { "allow": ["src/", "tests/"], "deny": ["src/generated/"] } }
   ```
   Пока файла нет, `implementer` в этом проекте ничего не может записать. Так задумано.
3. **Необязательно, для `/ui-review`:**
   - `projects/<id>/ui-review.json`: платформа, схема, bundle id, продукт, симулятор;
   - `projects/<id>/ui-review.md`: как попасть в нужные состояния экрана, дизайн-документы, правила текстов.
   Если файлов нет, скилл соберёт черновик и покажет вам.
4. **Необязательно, свои настройки журнала** — `projects/<id>/collab/*.json`: роли, раннеры, политика. Каждый файл целиком заменяет встроенный. Ослабить встроенную политику нельзя. Правило, понижающее класс, требует `"lowers_default": true` и обоснование, а `collab check-config` покажет его отдельно.
5. **Проверка, установка:**
   ```bash
   bin/collab check-config
   bin/agent-kit-install
   ```
   Файлы под `projects/<id>/` — `.gitignore` набора исключает их специально (см. «Что внутри» выше): здесь нечего коммитить, установщик читает их прямо с диска.
6. **В самом проекте, один раз:** `collab init`. Команда создаёт `.collab/` и исключает его из git через `.git/info/exclude`, файлы проекта не меняются.

Без записи в реестре проект тоже работает: встроенные нейтральные настройки, раннеров нет, `implementer` писать не может.

## Полезные команды

```bash
collab project --json        # какой проект, корень журнала, откуда настройки (ничего не пишет)
collab status | doctor       # состояние журнала
collab reviews --reviewer codex --pending
collab approvals             # что ждёт вашего одобрения
collab approve <id>          # только владелец, только в интерактивном терминале
collab init --adopt          # привязать перенесённый или старый журнал (только владелец, терминал)
```

## Разработка

```bash
node --test collab/test/                                    # журнал
/usr/bin/python3 -m unittest tests/test_scope_guard.py tests/test_readonly_guard.py
bash tests/test_ui_review_scripts.sh
node --test tests/test_install_*.mjs                        # установщик, ~3 мин (4 файла параллельно)
```

Коммит → `bin/agent-kit-install`. Изменения в реестре тоже вступают в силу только после установки.
