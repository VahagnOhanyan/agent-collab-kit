# agent-kit

Инструменты для совместной работы AI-агентов (Claude Code и Codex) в любом проекте на этой машине. Исходник — этот репозиторий; машина пользуется **установленным релизом** `~/.agent-kit/current`, а не рабочим деревом.

## Что внутри

| Часть | Что делает | Где |
|---|---|---|
| `collab` | Журнал агентов: задачи, ревью, решения, одобрения владельца. MCP-сервер + CLI | `collab/`, `bin/collab`, модель угроз — `collab/SECURITY.md` |
| `/codex-review` | Ручной запуск Codex на ждущие ревью из журнала | `skills/codex-review/` |
| `/ui-review` | Скриншот экрана → варианты дизайна от Codex → **одобрение владельца** → реализация → сравнение | `skills/ui-review/`, скрипты `ui-review/` |
| `implementer` | Агент-исполнитель; писать может только в области, заданные владельцем | `agents/implementer.md`, хук `hooks/scope-guard.mjs` |
| `verifier` | Агент-проверяющий, ничего не меняет | `agents/verifier.md`, хук `hooks/readonly-guard.mjs` |
| `model` обязателен в `Agent()` | Вызов субагента без явной `model` (кроме `subagent_type: "fork"`) отменяется до делегирования, а не ловится потом по транскрипту | `hooks/model-guard.mjs` — установщик сам вписывает его в `settings.json` каждого конфига Claude Code (`PreToolUse`, matcher `Agent`), поэтому он действует во всех проектах машины без строки в проекте. Чужие хуки в файле не трогаются, откат возвращает файл |
| План до правки кода | Правка файла под `plan_gate.paths` без текущего плана со строками «Маршрут:» и `ux_impact:` отменяется. Одна логика для ведущего Claude (`plan-gate`) и ведущего Codex (`codex-guard`); текущий план — последний, упомянутый в транскрипте сессии, иначе самый свежий | `hooks/plan-gate.mjs`, `hooks/lib/plan-gate.mjs`; установщик вписывает хук в `settings.json` каждого конфига Claude; настройка — `plan_gate: {"plans_dir", "paths"}` в `project.json` реестра проекта, без неё проверки нет |
| Push только через зелёный гейт | `git push` (в том числе внутри `sh -c` и цепочки) отменяется, пока гейт проекта красный; `--force`, `-f`, `--force-with-lease`, `+ref`, `--no-verify` отменяются всегда | `hooks/push-gate.mjs`; настройка — `gate` в `project.json` (скрипт, получает `--quiet`), без неё push проходит |
| Гейт после правки контракта | Правка файла под `post_edit[].paths` (или файла, названного в реестре) сразу запускает гейт правила; красный — код 2 с хвостом вывода | `hooks/post-edit.mjs`; настройка — `post_edit: [{gate, paths, registries}]` в `project.json` |
| Git-хуки проекта | При старте сессии включает `core.hooksPath` на каталог проекта (только если изменилось) | `hooks/session-start.mjs`; настройка — `githooks_dir` в `project.json` |
| `/adversarial-audit`, `/handoff` | Аудит с опровержением каждой находки отдельным агентом; документ передачи сессии | `skills/adversarial-audit/`, `skills/handoff/` |
| Хуки | Все хуки — Node (`hooks/*.mjs`), один код для macOS и Windows; хост запускает их через лаунчер `bin/agent-kit-hook <имя>` | `hooks/`, модель угроз — `hooks/SECURITY-hooks.md` |

**Платформы.** macOS и Windows; нужен Node 20.19+. На macOS проверено прогонами; на Windows код есть, но живой проверки ещё не было (см. `hooks/SECURITY-hooks.md`).
| Правило оркестрации | План до первой правки, уровни L0–L3, маршрутизация, слоты проверок; ставится в `~/.claude/rules/` | `rules/orchestration.md` |
| Правило терминологии | Любая задача начинается со словаря «термин → имя в коде → что видно», который владелец подтверждает до работы; ставится в `~/.claude/rules/` | `rules/terminology.md` |
| Реестр проектов | Доверенные настройки каждого подключённого проекта (вне самих репозиториев); заводится `collab connect` | `~/.agent-kit/projects/<id>/` |

Работа между моделями распределяется в двух местах, и это разделение намеренное. **Данные** — здесь: `collab/config/models.json` — лестница уровней L0–L3 и то, какую модель каждый уровень означает у каждого вендора (`collab models` показывает её, `collab doctor` сверяет id с каталогом вендора и сообщает дрейф). **Суждение** — план до первой правки, какой уровень у задачи, когда эскалировать и сколько нужно независимых проверок — в `rules/orchestration.md` этого репозитория (с 17.09.2026; раньше жило только в `~/.claude/rules/` без истории). Установщик кладёт копию в `~/.claude/rules/orchestration.md`, откуда её грузит каждая сессия Claude Code; править — здесь, а не копию: изменённая руками копия остановит следующую установку. Имена моделей в коде и скриптах не живут; они живут в реестре. Границы и остаточные риски хуков — `hooks/SECURITY-hooks.md`.

## Установка, проверка, откат

Установщик берёт **только закоммиченное** состояние: грязное дерево он откажется ставить.

```bash
bin/agent-kit-install --dry-run      # все проверки и тесты, ничего не меняет
bin/agent-kit-install                # установка
bin/agent-kit-install --rollback     # вернуть предыдущий релиз
```

Что делает установка:
1. Проверяет, что в коммите есть все обязательные файлы.
2. Собирает релиз через `git archive` и прогоняет в нём тесты `collab`: должно быть 0 падений и 0 пропусков.
3. Делает дымовой тест MCP: сверяет полный список инструментов и что без журнала ничего не создаётся.
4. Атомарно переключает `~/.agent-kit/current`.
5. Раскладывает по домашнему каталогу то, что читают Claude Code и человек: `<каталог настроек>/skills/{codex-review,ui-review}`, `<каталог настроек>/agents/{implementer,verifier}.md` и `<каталог настроек>/rules/{orchestration,modules,terminology}.md` — **в каждом каталоге настроек Claude Code**, не только в `~/.claude`. На macOS/Linux все три — **настоящие копии** из установленного релиза (симлинк здесь Claude Code не видит, проверено 16.09.2026), владение отслеживается по хэшу в `~/.agent-kit/posix-copies.json`. На Windows каталоги скиллов — junction на `current` (единственная ссылка, доступная без прав администратора), а файлы агентов и правила — копии, по хэшу в `~/.agent-kit/windows-links.json`. Лаунчер `collab` — симлинк в bindir (по умолчанию первый существующий из `/opt/homebrew/bin`, `/usr/local/bin` на macOS/Linux, `%LOCALAPPDATA%\Microsoft\WindowsApps` на Windows), на Windows — `.cmd`-шим, потому что симлинк на файл там без администратора недоступен. Чужой файл на месте копии не перезаписывается: установка откажет и назовёт его.
6. Регистрирует MCP `collab` для Claude (уровень пользователя, отдельно в каждом каталоге настроек) и Codex (`~/.codex/config.toml`, с бэкапом). Каталог, чей `claude` не отвечает (например, у аккаунта отключён доступ), попадает в вывод строкой «NOT registered» — установка при этом доходит до конца: копии важнее регистрации, а зарегистрировать можно потом. Это касается **дополнительных** каталогов; в основном (`~/.claude`) сбой регистрации по-прежнему отменяет установку целиком.

**Несколько аккаунтов Claude Code.** У каждого аккаунта свой каталог настроек (`~/.claude`, `~/.claude-account-2`, …), и сессия читает скиллы, агентов и правила **только из своего** — проверено 18.09.2026 файлом-меткой в каждом каталоге. Поэтому копии нужны в каждом: по умолчанию установщик берёт `~/.claude`, добавляет каталоги из повторяемого флага `--claude-config-dir <путь>` и подхватывает `CLAUDE_CONFIG_DIR`, если тот указывает внутрь домашнего каталога (сравниваются реальные пути: симлинк наружу дома не пройдёт) (снаружи — игнорирует, чтобы прогон тестов со своим `--home` не задел настоящий аккаунт; явно заданный снаружи путь — ошибка). Подсказка про откат в конце установки уже содержит нужные `--claude-config-dir`.

Любой сбой откатывает всё, что успело измениться. После установки перезапустите открытые сессии Claude и Codex.

## Свой состав агентов — один раз после установки

В agent-kit не зашит ни ведущий агент, ни вендор. Каталог (`collab/config/agents.json`) только описывает, что каждый вендор умеет и как вызывается. Кто есть у тебя, кто ведущий (агент, в котором ты работаешь) и кто в какой роли — твой состав:

```bash
collab setup --dry-run                       # что найдено на машине и что предлагается
collab setup                                 # спросит, кого включить и кто ведущий; только человек в терминале
collab setup --agents codex --lead codex     # то же без вопросов
```

Состав лежит в `~/.agent-kit/collab/agents.json` (вне git), его можно править руками или запускать `collab setup` снова. Проект может его сузить (`collab setup --project`). Один агент в составе получает все роли, которые ему по силам.

**Режим ревью** (`review_mode` в составе): `cross_vendor` — ревью никогда не уходит автору, нужен агент другой модельной семьи; `single_vendor` — у тебя один вендор, и ревью уходит тому же агенту в отдельной сессии, а в ревью записывается `independence: same_agent_separate_session`. `setup` ставит `single_vendor` сам, если все выбранные агенты одного вендора, или по флагу `--single-vendor`.

Правила доставляются ведущему в его формате: Claude Code — `~/.claude*/rules/` (в контексте целиком) и скиллы; Codex — управляемый блок в `~/.codex/AGENTS.md` (текст вне блока твой, установка его не трогает). Блок — указатель, а не копия: Codex читает не больше 32 КБ всех `AGENTS.md` вместе (`project_doc_max_bytes`), а правила больше. В блоке — какие файлы правил прочитать целиком перед работой и какую процедуру (скилл Claude Code, для Codex — обычный текст) читать для какой работы, с путями в установленном релизе. Чем понятия правил («разведчик», «режим плана», хуки) выражаются у каждого хоста — раздел «Хост ведущей сессии» в `rules/orchestration.md`.

## Подключить проект

В папке любого проекта, в своём терминале:

```bash
collab connect --dry-run     # показать, что будет записано (можно откуда угодно, даже агенту)
collab connect [--id <id>]   # подключить: только человек, только интерактивный терминал
```

`connect` смотрит на сам проект и предлагает:
- `project.json` — id (по умолчанию имя папки), корень (все worktree репозитория пишут в один журнал), `gate` — `scripts/preflight.sh`, если он есть и исполняемый; его запускает `verifier`;
- `scopes.json` — куда может писать `implementer`: все отслеживаемые git верхнеуровневые папки и файлы, кроме скрытых (`.git`, `.claude`, `.collab`, `.mcp.json` хук запрещает всегда);
- `readonly-guard.json` — группа `apple` для `verifier`, если в проекте есть `*.xcodeproj`, `*.xcworkspace` или `Package.swift`;
- журнал `.collab/` (как `collab init`).

Записывает после того, как вы наберёте id проекта. Реестр лежит в `~/.agent-kit/projects/<id>/` и читается напрямую — переустанавливать набор не нужно; открытые сессии проекта перезапустить. Проект находится по пути: сессия в любой папке внутри корня видит его настройки.

Предложенное можно поправить в `~/.agent-kit/projects/<id>/` руками:
- `scopes.json` — `{ "implementer": { "allow": ["src/", "tests/"], "deny": ["src/generated/"] } }`; проектным субагентам — свои секции по их `KIT_AGENT`;
- `ui-review.json` / `ui-review.md` — для `/ui-review`: платформа, схема, bundle id, симулятор; как попасть в нужные состояния экрана;
- `collab/*.json` — роли, раннеры, политика; каждый файл целиком заменяет встроенный, ослабить встроенную политику нельзя, понижающее правило требует `"lowers_default": true` и обоснование. `collab check-config` проверит всё.

Отключить: `collab disconnect` в папке проекта (тоже только человек). Журнал `.collab/` остаётся.

**План до правки для ведущего Codex.** Если в `project.json` проекта добавить `"plan_gate": { "plans_dir": "<каталог планов>", "paths": ["src/", …] }`, хук `codex-guard` не даст ведущему Codex править эти пути без плана со строками «Маршрут:» и `ux_impact:` (план — последний упомянутый в сессии, иначе самый свежий). Хук ставится установкой в `~/.codex/hooks.json`; Codex запустит его только после того, как ты один раз подтвердишь его командой `/hooks` в Codex.

Без подключения collab в проекте тоже работает, но урезанно: встроенные настройки, раннеров нет, `implementer` писать не может, платформенные команды `verifier` закрыты.

## Полезные команды

```bash
collab project --json        # какой проект, корень журнала, откуда настройки (ничего не пишет)
collab status | doctor       # состояние журнала
collab reviews --reviewer codex --pending
collab approvals             # что ждёт вашего одобрения
collab approve <id>          # только владелец, только в интерактивном терминале
collab init --adopt          # привязать перенесённый или старый журнал (только владелец, терминал)
```

## Веб-панель (только чтение)

```bash
collab ui                    # поднимает панель на 127.0.0.1, печатает адрес с токеном и открывает браузер
collab ui --no-open --port 4870 [--project <id>]
```

Панель — страница в браузере над теми же данными, что показывают `collab status | tasks | approvals | doctor`: задачи и ревью, что ждёт вашего решения, лента событий в реальном времени, состав и роли, скиллы и агенты набора и **мастер настройки**. Она ничего не записывает и не выдаёт одобрений: права агентам выдаёт только владелец в своём терминале, поэтому мастер собирает выбор и показывает готовые команды (`collab setup …`, `collab connect --dry-run`) с кнопкой «Копировать», а кнопка «Проверить» перечитывает `doctor`.

```
Браузер ── HTTP 127.0.0.1 (токен, Host-проверка, CSP) ──► ui/server.mjs
                                                            │ createApi({ readOnly: true })
                                                            ▼
                                 .collab/ · реестр проекта · skills/ agents/ rules/
```

- Данные не дублируются: журнал читается через `createApi({ readOnly: true })` (пишущие методы и фоновая уборка аренд выключены), скиллы, агенты и правила — из файлов набора. Списка «что есть» в панели нет.
- Добавить экран: эндпоинт в `ui/server.mjs`, функция «api → JSON» в `ui/views.mjs`, отрисовка в `ui/public/app.js` (только `textContent`: текст журнала пишут агенты, это недоверенный ввод), тест в `ui/test/`.
- Отладка: адрес и токен печатает команда; `403` — открыли без токена или с чужим `Host`; данных нет — `collab project --json` покажет, какой журнал видит панель.
- Границы: слушает только `127.0.0.1`, только `GET`/`HEAD`, без CORS. Запуск команд и ответ на одобрения из браузера — сознательно вне панели. Токен в адресе виден другим пользователям этой машины в списке процессов (`ps`) на время открытия браузера: панель рассчитана на личный компьютер.

## Разработка

```bash
node --test collab/test/ ui/test/                           # журнал и панель
node --test tests/test_*_guard.mjs tests/test_agent_hook_commands.mjs   # хуки, ~40 с
bash tests/test_ui_review_scripts.sh
node --test tests/test_install_*.mjs                        # установщик, ~3 мин (4 файла параллельно)
```

Коммит → `bin/agent-kit-install`. Изменения в реестре тоже вступают в силу только после установки.
