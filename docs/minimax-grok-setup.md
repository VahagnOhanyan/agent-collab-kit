# Настройка MiniMax и Grok

## Назначение и границы

Запрошена настройка набора для MiniMax и Grok. Предлагаемый состав: Codex ведёт
работу и принимает результат, MiniMax выполняет обычные задачи реализации, Grok даёт
независимое ревью и анализ. 3 октября 2026 владелец уточнил состав: роли гибкие —
все трое держат реализацию, исследование, архитектуру и ревью, а выбор исполнителя
делается по задаче. Ограничение «Grok только ревью» снято; правила ревью при этом
остались отдельными и строгими. Авторизацию Grok нужно обновить: действующий профиль
возвращает 401 при обновлении истёкшей сессии.

Текущая работа локальная. Существующие исправления установщика, блокировок, README
и тестов сохраняются. Первоначальная настройка выполнялась локально. 3 октября 2026
владелец отдельно разрешил коммит, push и создание PR; установка и публикация релиза
в этот запрос не входят. Утверждение «на машине нет установленного agent-collab-kit»
относится к 2 октября 2026 и верно на ту дату; с тех пор появилась базовая копия
набора — `~/.agent-collab-kit/current`, и проверки этой ветки выполняются против её исходников, а не установленной копии. Активация
предлагаемого состава в машинном профиле не подтверждена.

## Клиенты и маршруты

- MiniMax: уже существующий `~/.local/bin/minimax-dev`, закреплённый маршрут `minimax-coding-plan/MiniMax-M3.1-Flash-Preview` через OpenCode; основная и вспомогательная модели совпадают, GPT fallback отсутствует.
- Grok: официальный `@xai-official/grok` 1.0.34 из локального provider-tools; профиль `~/.config/ai-harness/grok`. Локальный каталог от 18 сентября содержит `grok-4.5` и `grok-4.6`; он не доказывает текущий доступ. Тот же CLI обслуживает и реализацию, и ревью: read-only с отключёнными субагентами — способ запустить конкретное ревью, а не свойство клиента и не запрет на реализацию.
- Сам набор не запускает платные процессы автоматически. Новые агенты добавляются как manual/headless клиенты. Ведущий запускает ограниченную задачу отдельной командой.

## Критерии готовности

1. Реестр знает агентов `minimax` и `grok` и их модели; проверка реестра зелёная.
2. MiniMax вызывает только существующий закреплённый launcher; его настройки подписки сохраняются.
3. У Grok одна команда на обе роли; для ревью есть отдельный запуск с read-only sandbox, а модель и режим разрешений не переключаются скрыто.
4. Предлагаемый состав даёт всем троим реализацию, исследование, архитектуру и ревью, и не оставляет автора единственным ревьюером собственной работы.
5. Проверки CLI/MCP выполняются без вызова модели и без копирования секретов в репозиторий, задания или отчёт.
6. Реальная установка и проверка model inference отмечаются отдельно от подготовки конфигурации. Не заявлять их завершёнными без соответствующих проверок.

Изолированный Grok: `grok --version`, `grok --help`, `grok mcp add`, `grok mcp list --json`. Проба настоящей модели выполняется только после обновления входа и согласования расхода лимита.

## Что добавлено в каталог набора

Конфигурация клиентов и явная политика остановки для preview-модели без запасного маршрута.

- `collab/config/agents.json`: агент `minimax` (provider `minimax`, определяется командой `minimax-dev`) и агент `grok` (provider `xai`, определяется командой `grok`). Оба — `manual`, без автозапуска и без аргументов запуска: сообщение попадает в их inbox, а процесс начинает человек или ведущий агент из своей оболочки. `adapter.cannot` пуст у обоих — это факт о программе, а не о роли: урезанный read-only запуск ревью задаётся при запуске, а не свойством клиента.
- `collab/config/briefings/minimax.md`, `collab/config/briefings/grok.md`: инструкции агентам. MiniMax — в основном реализация ограниченной задачи, с сохранением чужих изменённых файлов, проверками и независимым ревью по роли; запуск UI он не объявляет проверенным. Grok — две процедуры: полная процедура исполнителя (рамки задания, `claim_task`/`claim_files`, проверки, отчёт о непроверенном, независимый review по роли) и отдельная, более строгая процедура ревью (без правок, без делегирования, без платного запуска без разрешения владельца). Оба брифа указывают, что роль ревьюера не единственная и не постоянная. Роли в каталоге не зашиты: это решение машины (`collab setup`).
- `collab/config/models.json`: поставщики `minimax` (единственный ref `minimax-worker`, id `MiniMax-M3.1-Flash-Preview`, L1/max L2) и `xai` (refs `grok-basic` id `grok-4.5` L1/max L2 и `grok-review` id `grok-4.6` L2/max L3). У обоих `catalog_file: null` и `verified: unverified`; перекрёстного fallback между поставщиками нет.
- `collab/test/minimax-grok.test.mjs`: проверка, что оба агента в каталоге, ручной режим без автозапуска, верный provider, закреплённые id и отсутствие выдуманных полей (цена, контекст, capabilities). Вторая половина файла применяет `docs/minimax-grok-composition.proposed.json` как настоящий машинный состав (временный каталог через `writeComposition` + `loadConfig`) и проверяет, что он валиден, ведёт Codex, работает в `cross_vendor`, даёт всем троим реализацию/исследование/архитектуру/ревью без ролей, которых их capabilities не поддерживают, и что у каждого автора есть другой ревьюер.

## Как запускать

Все команды запускаются вручную; набор сам ничего не стартует и не обходит разрешения.

MiniMax — одна команда, оба пути абсолютные, задание лежит в файле:

```
minimax-dev --dir /absolute/path/to/project --task-file /absolute/path/to/task.md
```

Grok — та же форма для задания на реализацию (флаги сверены с `grok --help` 1.0.34, без вызова модели):

```
grok --model MODEL_ID --cwd /absolute/path/to/project --prompt-file /absolute/path/to/task.md
```

и отдельный запуск для ревью, с защищённым деревом:

```
grok --model MODEL_ID --cwd /absolute/path/to/project --sandbox read-only --no-subagents \
      --prompt-file /absolute/path/to/review.md
```

Read-only — свойство этого вызова, а не режим Grok и не запрет на реализацию. Обёртка `grok-review` (ниже) задаёт его для конкретного ревью, а не «для Grok вообще».

Модель (`--model`) и режим разрешений (`--permission-mode`) выбирает владелец при запуске: в каталоге их нет, и агент не переключает их молча. Бинарь Grok лежит в `~/.local/share/ai-harness-provider-tools/node_modules/@xai-official/grok/bin/grok`; локальная обёртка `~/.local/bin/grok` уже добавлена в PATH-профиль этой машины. Профиль: `GROK_HOME=~/.config/ai-harness/grok`. Регистрация collab — секция `[mcp_servers.collab]` с `COLLAB_AGENT_ID=grok` в `$GROK_HOME/config.toml`; установщик набора пишет этот файл для Claude, Codex, Gemini и Cursor, но не для Grok, поэтому секция добавляется руками один раз.

## Что осталось непроверенным

- MiniMax выполнил эту настройку через существующий launcher. Живой вызов Grok не выполнялся. `minimax-dev --check` подтверждает только, что launcher принимает маршрут `minimax-coding-plan/MiniMax-M3.1-Flash-Preview`; это не независимый каталог поставщика.
- Grok: id `grok-4.6` и `grok-4.5` взяты из локального сохранённого каталога от 18 сентября, обновление каталога вернуло 401 (сессия истекла). Ни доступность этих id, ни то, что sandbox держит, не подтверждены. Значения секретов не копировались в задания или отчёты.

MiniMax имеет `maturity: preview`, `fallback: null`, `fallback_policy: stop`: при сбое нужна помощь владельца, автоматического перехода на другую модель нет. Grok-модели остаются непроверенными.

Локальные команды уже добавлены в `~/.local/bin`: `grok` использует профиль `~/.config/ai-harness/grok`, а `grok-review /absolute/project/path /absolute/task.md` закрепляет `grok-4.6`, read-only sandbox, отключает субагентов и MCP-вызовы, ограничивает запуск шестью ходами. Это удобный способ запустить одно ревью, а не универсальный способ работы Grok: задание на реализацию идёт через `grok` без этих ограничений. Результат такого ревью возвращается ведущему; оно не записывает `submit_review` в журнал автоматически. Проверена передача аргументов через подставной CLI, без расхода лимита Grok.

## Итог локальной проверки

Исполнитель поддержки клиентов: существующий MiniMax launcher; завершился с кодом 0. Координатор исправил интеграционные фикстуры, статус Preview и отображение отсутствующей цены. Проверено на Node 22.22.0: 427 тестов collab/панели и 221 тест установщика/хуков, все прошли. Для установщика используется `AGENT_COLLAB_KIT_TEST_SOURCE="$PWD"`; первый запуск без этой переменной искал исходники в отсутствующем `~/agent-collab-kit`. Проверены `check-config`, `git diff --check`, синтаксис shell-обёрток и передача параметров без model inference.

`minimax-grok-composition.proposed.json` — проверенный проект состава: Codex ведёт, а все трое держат реализацию, исследование, архитектуру и ревью; выбор исполнителя делается по задаче, `review_mode: cross_vendor`, и автор никогда не остаётся единственным ревьюером своей работы. Файл пока не активирован в машинном профиле.

Основной agent-collab-kit на 2 октября 2026 на машине не был установлен — это верно на ту дату. С тех пор доступна базовая копия набора (`~/.agent-collab-kit/current`), но текущая правка проверена в рабочей ветке и не установлена. Установщик архивирует только чистый committed HEAD и отвергает незакоммиченные изменения. Разрешение владельца на коммит, push и PR получено 3 октября 2026. Последующие шаги активации: установка, подключение MCP клиентов к стабильному `~/.agent-collab-kit/current`, применение этого состава владельцем и обновление входа Grok. До этого не заявляется ни активация состава, ни живое взаимодействие клиентов через журнал.

`MODEL_ID` в примерах заменяется явным id из проверенного реестра. Ревью назначается по риску и независимому аспекту проверки, без постоянного закрепления за вендором и без лишних кругов для механических задач.
