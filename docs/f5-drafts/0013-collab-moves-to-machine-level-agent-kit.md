# 0013 — Слой совместной работы агентов переезжает в машинный набор `~/agent-kit`

- **Дата:** 2026-09-12 · **Статус:** CONFIRMED (решение владельца). Дополняет [ADR-0011](0011-multi-agent-collaboration-layer.md) — тот же протокол, новое место и новые гарантии; 0011 не отменяется.

## Контекст

`tools/collab/` жил внутри Tripix и был на неё жёстко завязан: код, конфиг агентов, раннеры и установка Codex — всё в одном репозитории, по путям, которые существуют только в одном рабочем дереве. Это ломалось на первом же выходе за пределы Tripix: регистрация MCP-сервера у Codex — `~/.codex/config.toml`, файл уровня пользователя, — и указывала на сервер по абсолютному пути внутрь `~/Tripix`. Значит, Codex, запущенный из **любого другого** проекта на этой машине, всё равно находил `collab` и писал задачи чужого проекта в журнал Tripix — агент и владелец могли не заметить, что подмешалось не то дерево.

При этом слой владельцу нужен не только в Tripix: WeSpace/brockerApp, Aweiro Learning и любой следующий проект получили бы ту же пользу — общее состояние агентов вместо прозы в контексте. Копировать `tools/collab/` в каждый репозиторий значит поддерживать N расходящихся копий одного и того же гейта одобрений: правка гарантии в одном месте не долетала бы до остальных.

## Решение

1. **Код слоя — отдельный репозиторий `~/agent-kit`.** Машина пользуется **установленным релизом** `~/.agent-kit/current` (симлинк, атомарно переключаемый `bin/agent-kit-install`), а не рабочим деревом набора: установщик берёт только закоммиченное состояние и гоняет тесты `collab` внутри собранного релиза (0 падений, 0 пропусков) до переключения.
2. **Доверенный реестр проектов вне репозиториев** — `~/agent-kit/projects/<id>/`. `project.json` называет `roots` (корень журнала) и `gate`; `scopes.json` — куда может писать `implementer` (нет файла — писать нельзя вообще); `collab/*.json` (`agents`, `roles`, `capabilities`, `policy`, `runners`) целиком заменяют встроенные того же имени и могут только ужесточать классификацию, кроме правил с `lowers_default` и обоснованием. **Конфиг и раннеры приходят только из этого реестра** — никогда из `.mcp.json` проекта и никогда из окружения: иначе любой репозиторий на машине мог бы объявить себе более мягкую политику одобрений или свой список исполняемых команд.
3. **Журнал не появляется сам.** Единственный способ завести `.collab/` — явный `collab init` в корне журнала; команда добавляет `.collab/` в `.git/info/exclude` (через общий `info/exclude` git common dir) и не трогает файлы проекта. Ранее слой в Tripix создавал состояние implicitно при первом вызове — то же свойство, из-за которого чужой Codex мог незаметно завести или дописать журнал не в том дереве.
4. **Один журнал на все worktree одного репозитория.** Корень журнала — родитель git common dir, а не текущего рабочего дерева, поэтому `.claude/worktrees/map-pin-spatial-grouping` и основной чекаут Tripix пишут в один и тот же `.collab/`.

## Отвергнуто

- **Копия слоя в каждом репозитории.** N расходящихся копий одного гейта одобрений — правка одной гарантии не долетает до остальных.
- **Проект сам объявляет свой конфиг (`.mcp.json`, файл в дереве).** Тогда чужой или скомпрометированный репозиторий на той же машине мог бы понизить себе класс действий или подменить раннер. Источник конфигурации обязан быть вне репозитория, которым он управляет.
- **Оставить неявное создание журнала.** Это и есть механизм, из-за которого работа над чужим проектом тихо утекала в журнал Tripix; `collab init` делает привязку видимым, разовым действием.

## Последствия

- **CI Tripix (`config-guards.yml`) больше не проверяет конфиг collab.** Машинного реестра `~/agent-kit` в CI-раннере нет и не должно быть — проверять там нечего; шаг `Collab agent registry and approval surface` удалён.
- **`scripts/preflight.sh` проверяет реестр, только когда набор установлен.** Есть `collab` на `PATH` — гоняется `collab check-config --project tripix`; нет — печатается некрасная строка «collab не установлен — проверка реестра пропущена», и preflight не врёт зелёным про непрогнанную проверку (см. `docs/tooling/collab.md#если-что-то-не-так`).
- **Worktree на старых ветках отстают, а не ломаются.** `.claude/worktrees/*`, где ещё лежат старый `.mcp.json` и `tools/collab/`, продолжают работать на старом коде до ребейза на `main` — формат журнала совместим (проверено), поэтому задачи видны те же, просто через старый путь.

## Гарантии теперь обеспечены

Из модели угроз набора (`~/agent-kit/collab/SECURITY.md`) — то же, что декларировал ADR-0011, теперь проверяется машинно и вынесено из-под контроля отдельного репозитория:

- **Один гейт на вход в `in_progress`** (`domain/gate.mjs`): легальное ребро перехода, вызывающий вправе держать задачу (владелец, ничья или протухший лиз), у него есть нужная роль, и решает политика. Обойти гейт нельзя ни одним путём в работу.
- **Гранты одноразовые**, привязаны к отпечатку действия и потребляются в той же транзакции, что стартует работу.
- **Изменение статуса — только владелец.** `collab approve|reject` и `collab init --adopt` отказывают, когда выставлен `COLLAB_AGENT_ID` (есть в любом шелле агента) или нет интерактивного терминала, и требуют повторного ввода id заявки / корня журнала.
- **Окружение — не вход.** `COLLAB_CONFIG_DIR`, `COLLAB_REGISTRY_DIR`, `COLLAB_PROJECT_ROOT`, `COLLAB_STATE_DIR` игнорируются и репортятся; git выбирается рабочим `--version`-пробником по фиксированным путям, а не по `PATH`.
- **Отслеживаемый или скопированный журнал отвергается.** `collab init` — единственный создатель `.collab/`; символьные ссылки, пустые/недостроенные и git-tracked журналы отказываются; маркер, привязанный к другому корню, — тоже. Markerless legacy-журнал (как у Tripix) принимается только когда реестр явно ставит `"legacy_journal": true`.

## Остаточные риски

- **TOCTOU пути раннера** — путь проверяется, потом процесс стартует; подмена симлинком между этими шагами не ловится (Node не даёт openat-подобного spawn).
- **Коммит не атомарен между файлами** — при падении посреди транзакции грант может оказаться потрачен без начатой работы, никогда наоборот; это лечится повторным запросом к владельцу, не автоматикой.
- **Подделка тем же пользователем.** Оба агента — один OS-пользователь с шеллом; это не граница безопасности против решительного процесса (см. «Честная граница» в `docs/tooling/collab.md`).
- **Фиксированный `PATH` — не якорь доверия**: в нём есть пользовательские каталоги (Homebrew Cellar, `/opt/homebrew/bin`).
- **`legacy_journal: true` доверяет журналу без проверки маркера** ровно тому корню, что в реестре, пока владелец не выполнит `collab init --adopt`.

## Откат

`~/agent-kit/bin/agent-kit-install --rollback` возвращает предыдущий установленный релиз набора (симлинки скиллов/агентов/`collab`, обе MCP-регистрации) — без изменений в Tripix.

Возврат самого слоя в Tripix — обычный `git revert` коммита, которым сделан этот переход: `tools/collab/`, запись `collab` в `.mcp.json` и копии скиллов возвращаются как были. `.collab/` не в git, поэтому переключение туда-обратно его не трогает; формат журнала общий для старого и нового кода.
