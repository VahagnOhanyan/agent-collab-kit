# handoff — следующая сессия начинает с документа, а не с переписки

Что не записано — потеряно: контекст сессии не переживает `/clear`, auto-memory живёт на одной машине, а `*.md`, попавший в `.gitignore`, не уедет в репозиторий, пока его не добавили силой. Образец — предыдущий законченный handoff проекта (`docs/session-handoff-*.md`), если он есть.

Каталог документов, формат ADR и постоянные ограничения работы задают правила проекта (`CLAUDE.md`, `.claude/rules/`); ниже — значения по умолчанию.

## 1. Снять состояние — командами, не по памяти
```bash
git rev-parse --short HEAD; git status --porcelain; git log --oneline @{upstream}..HEAD | wc -l
git diff --stat            # что не закоммичено; чужой WIP — отдельно от своего
```

## 2. Написать `docs/session-handoff-<ГГГГ-ММ-ДД>.md`
Самодостаточно: читатель не видел переписки. Конкретика, без «должно работать»; язык — как у проекта.

```markdown
# Передача сессии — <дата>

<Одним абзацем: над чем шла работа и на чём остановилась.>

**Состояние репозитория:** ветка `<имя>` = `<sha>`, дерево <чистое | N файлов не закоммичено: …>,
впереди upstream на N коммитов — <запушено | не запушено>.

## Часть 1. Сделано и закоммичено
### A. <задача>
**Проблема.** … **Решение.** файлы, ключевые константы/инварианты (проверены в коде <дата>).
⛔ Грабли, на которые уже наступили: … (что НЕ работает и почему — дороже всего)
**Проверено:** команды и результат. **Не проверено:** прямо.

## Часть 2. Найдено, не исправлено
Улики (лог/файл:строка) → причина → предлагаемое решение → ⚠️ порядок работ.

## Часть 3. Хвосты и как продолжать
- Не проверено на устройстве / в проде: …
- Точечные тесты для ручного прогона: <классы или команды>; что не запускалось — прямо.
- Ловушки: …
- Постоянные ограничения проекта (кто пушит, какие ветки, что запускается только вручную).
```

## 3. Решения — в репозиторий, не только в память
Если в сессии принято или отменено решение, которое должно связывать всех (инвариант, отвергнутая гипотеза) — ADR в каталоге решений проекта (по умолчанию `docs/decisions/<NNNN>-<slug>.md`) по его формату (контекст · решение · отвергнуто · последствия · где закреплено гейтом) и строка в его оглавлении. Изменение старого решения — новый ADR с `Supersedes`.

## 4. Память — указатели и ⛔, не пересказ
В auto-memory сессии (каталог назван в системном промпте) — один файл на факт, с `**Why**` и `**How to apply**`; строка-указатель в `MEMORY.md`. То, что уже в ADR или в коде, в память не дублировать.

## 5. Добавить в git
```bash
git add -f docs/session-handoff-<дата>.md      # если *.md игнорируется — без -f документ останется на одной машине
git add docs/decisions/<NNNN>-<slug>.md docs/decisions/README.md
```
Если в проекте есть проверка путей в правилах (CLAUDE.md, ADR), прогнать её перед коммитом. Коммит — только по просьбе владельца: в заголовке поведение, в теле что проверено, трейлеры — по правилам проекта. Явные пути в `git commit -- <пути>`: индекс общий с другими сессиями.

## Что делает handoff плохим
- Состояние «по памяти» вместо вывода команд.
- «Работает» без команды, которой это показано.
- Хвосты без порядка работ (что первым, что заблокировано чем).
- Решение, записанное только в память или только в переписку.
