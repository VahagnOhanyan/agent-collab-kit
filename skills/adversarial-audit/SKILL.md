# adversarial-audit — находка без опровержения ещё не находка

Аудит, который сразу удаляет по списку, удаляет живое: в аудите мёртвого кода четверть находок (62 из 244) была опровергнута вторым проходом, три пункта плана чистки отменились уже при исполнении. Обратный урок: 81 агент и 5M токенов поверх файлов, которые в это время редактировались, — синтез критиковал правку в полёте как баг.

Где лежат отчёты, планы и ADR — говорят правила проекта (`CLAUDE.md`, `.claude/rules/`); ниже — значения по умолчанию.

## 0. Заморозить дерево — иначе не запускать
- Ничего не редактировать, пока идёт фан-аут. Если правки нужны параллельно — агенты читают **снимок**: `git archive HEAD | tar -x -C <scratchpad>/snapshot`, и каждый промпт указывает этот путь.
- Записать `git rev-parse --short HEAD` и `git status --porcelain` в шапку отчёта: находка привязана к точке.
- Каталоги с копиями дерева (worktrees, сборки, вендорные каталоги) исключить из поиска. Если оболочка подменяет `grep` обёрткой, уважающей `.gitignore`, документацию, попавшую в игнор, искать системным `/usr/bin/grep`.

## 1. Собрать кандидатов — механически и через линзы
- Механические сканы (символ без ссылок, экспорт без импорта, роут без клиента, флаг без чтения, файл вне таргета) — read-only агенты разведки (`Explore`) на дешёвой модели, по одному на область проекта.
- Каждый кандидат — строка: **утверждение** · **улика** (файл:строка, команда) · **фальсификатор** (что было бы видно, будь утверждение ложным). Без фальсификатора строка не идёт дальше.

## 2. Опровергнуть каждую — отдельным агентом
Один агент на находку (волнами ≤ 10 параллельно, read-only, без Edit/Write; модель указывать явно). Промпт:
```
Опровергни утверждение: «<утверждение>». Улика автора: <улика>.
Ищи по КОДУ (все таргеты и области, тесты, ресурсы и каталоги строк, конфиги сборки, DI-графы,
строковые ссылки, отладочные ветки, рефлексия и динамический вызов) и по ИСТОРИИ
(`git log -S '<символ>' --oneline`, `git log --follow`, комментарии рядом:
«временно выключено», «до подтверждения»).
Дерево/снимок: <путь>, точка: <sha>.
Вердикт одним словом первой строкой — CONFIRMED / PARTIAL / CONTRADICTED — затем цитаты
(файл:строка) и что изменилось бы, будь вердикт другим. Не предлагай правок.
```
- **Ноль выживших = ноль находок**, а не «всё равно прочитаю синтез». Синтез поверх пустого списка — брейншторм; каждое его утверждение проверяется отдельно.
- Посылка умерла (одна улика обнулила весь класс находок) — **убить фан-аут**, не дожидаться.
- Лог с устройства или вывод команды выше любого числа агентов, рассуждающих о коде.

## 3. Бюджет
- Дешёвая последовательная разведка **до** параллелизма: замкнуть причинную цепочку четырьмя вызовами инструментов, а не 35 агентами на неверной посылке.
- Волна — не больше десяти агентов; следующая только после чтения вердиктов первой.
- Один аудит — одна тема. Смешивать «мёртвый код» и «архитектуру» — получить два плохих отчёта.

## 4. Отчёт
Файл `<каталог аудитов проекта>/<ТЕМА>_<ГГГГ-ММ-ДД>.md` (по умолчанию `docs/audit/`); если `*.md` в проекте игнорируется git'ом, а отчёт должен дожить до CI или другой машины — добавить принудительно (`git add -f`):
- шапка: точка (`sha`), метод (сколько агентов, сколько проверок), таблица вердиктов по областям;
- «Опровергнуто» — **обязательный** раздел с причинами: это карта ловушек для следующего аудита;
- «Отложено сознательно» — что живое по чужому решению (контракт-тест, протокол, комментарий «до подтверждения»);
- находки — только CONFIRMED и PARTIAL, каждая с выводом проверяющего, не автора.

## 5. Из аудита в план — не напрямую в удаление
Чистка по отчёту идёт **по пунктам с перепроверкой на месте** (поиск перед каждым удалением: файл мог ожить с момента снимка), через исполнителей проекта, с независимой проверкой (`verifier`) в конце. Инварианты, найденные по дороге, — в ADR проекта, не только в память.
